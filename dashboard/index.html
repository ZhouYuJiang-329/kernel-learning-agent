快速开始

这个 Dashboard 是 kernel-learning 的本地学习状态面板，读取 .claude/memory/、learn/ 和 dashboard/manual_edges.json，不直接分析内核源码。源码分析、memory 更新和笔记生成仍通过 Claude 会话完成。

# 1. 在工程目录启动 Claude，让项目级 CLAUDE.md 生效
cd /path/to/kernel-learning-workspace && claude

# 2. Claude 启动后应先读取 memory，并输出类似：
已加载学习上下文，当前有 N 个开放问题，最近学习了 XXX。
# 3. 启动 Dashboard
cd /path/to/kernel-learning-workspace/dashboard && ./start.sh

# 浏览器打开：
http://localhost:7788
提示：start.sh 会复用已运行的服务。关闭面板服务用 cd /path/to/kernel-learning-workspace/dashboard && ./stop.sh。

Dashboard 页面怎么读

页面
总览
展示总体进度、知识节点数量、开放问题数量、已解答问题数量，以及 MEMORY.md 中的当前学习焦点。
页面
知识图谱
提供两种视图：知识依赖图来自 memory/*/dep-graph.md；调用链路图来自 learn/**/*.md 里的调用树代码块和手动添加的调用链。
页面
节点列表
按子系统、状态和置信度浏览 knowledge.md 节点，适合快速确认某个函数/结构体是否已经分析过。
页面
开放问题
读取 open-questions.md，按 CRITICAL / MEDIUM / LOW 展示遗留问题和已解答记录。
页面
问答日志
合并 memory/*/qa-log.md，用于回看之前已经问清楚的关键结论。
页面
学习文档
扫描 learn/**/*.md，支持按子系统浏览和全文搜索，适合直接阅读函数级笔记、路线图和 synthesis 文档。
刷新机制：浏览器通过 /api/stream SSE 监听变化。修改 memory、learn 文档或手动调用链后，通常 3 秒内自动刷新；连接异常时会回退到 /api/data 拉取一次数据。

Claude 工作流

每次会话启动

  1. 先读取 .claude/memory/MEMORY.md 和 .claude/memory/open-questions.md。
  2. 用一句话确认当前开放问题数量和最近学习内容。
  3. 后续回答默认使用中文。

分析函数 / 结构体

你说："解释 enqueue_task_fair 的流程"
你说："分析 sched_entity 结构体"
你说："pick_next_task_fair 的调用链是什么"
lookup_status.sh 预检查→ 必要时查 Confluence→ kernel-graph MCP 查询→ 输出分析→ kernel-learning-capture 更新 memory

项目配置要求：提到具体函数名时，Claude 不能凭记忆写路径、行号或调用关系，必须先查 kernel-graph MCP；分析完成后要立即 capture，维护 Dashboard 的数据来源。

遇到遗留问题

你说："这个先放着" 或 "之后再看"

Claude 会写入 open-questions.md，按 CRITICAL / MEDIUM / LOW 管理。Dashboard 的“开放问题”页会自动显示。

模块级整理

你说："帮我理清这些文档"
你说："生成 sched 的状态矩阵"
你说："这个背后的理论是什么"

kernel-learning-synthesizer 负责把已有函数笔记串成路径、术语表、状态矩阵；kernel-concept-mapper 负责沉淀理论背景和概念债。两者输出后都会被“学习文档”页扫描到。

知识图谱使用

知识依赖图

默认模式。它来自 .claude/memory/{subsystem}/dep-graph.md，更适合回答“下一步读哪个节点”。下方“推荐阅读顺序”会根据节点状态和依赖关系排序，跳过已掌握节点。

调用链路图

切到“调用链路图”后，Dashboard 会扫描 learn/**/*.md 中无语言标签的调用树代码块，并合并 dashboard/manual_edges.json。紫色节点表示笔记里出现过、但还没有进入 knowledge.md 的函数。

搜索、筛选和聚焦

  1. 在搜索框输入函数名，按 Enter 定位节点。
  2. 用子系统按钮隐藏或显示某个模块，搜索命中被隐藏时会自动恢复显示。
  3. 定位节点后可启用 N 跳聚焦，只看当前节点附近的关系。
  4. 图谱拖拽或缩放到找不到节点时，点“重置视图”。

手动添加调用链

点击“+ 手动添加调用链”，粘贴 kernel-graph 或笔记里的 ASCII 调用树。保存后会写入 dashboard/manual_edges.json，并自动合并到调用链路图。

foo_init
└─ foo_register
└─ foo_enable
解析规则：上层是调用者，下层是被调用者；空行会重置一棵树；WARN_ON、BUG_ON、return 这类噪声会被过滤。

学习文档检索

“学习文档”页读取 learn/ 下所有 Markdown。左侧按子系统和目录组织，右侧渲染正文。搜索框会做全文匹配，并显示路径、文件名和命中的片段。

  1. 读路线图：打开 learn/{module}/{module}_read_guide.md。
  2. 读函数分析：打开具体函数名对应的 Markdown。
  3. 读模块整理：打开 learn/{module}/synthesis/ 下的术语表、路径索引或状态矩阵。
  4. 发现文档缺口：回到 Claude 会话中请求分析或整理，写入后的新文档会自动出现在这里。

新增学习板块

当你想开始学一个新的内核子系统时，一句话完成全部初始化。

第一步：触发 add-learning-module

你说："我要开始学 kprobe"

Claude 自动完成以下所有操作：

  1. 并行查询：kernel-graph MCP 查入口函数定位 + Confluence 搜索内部文档
  2. 初始化 memory/kprobe/：创建 knowledge.md（入口函数初始节点，全部 unknown）、dep-graph.md、qa-log.md，并更新 MEMORY.md
  3. CLAUDE.md 追加速查节：该子系统的关键路径和本地源码路径
  4. 创建 learn/kprobe/ 目录 + _index.md（Obsidian 目录页）
  5. 生成 kprobe-specialist agent：含该子系统背景知识的专属分析代理
  6. 自动触发 kernel-reading-guide：无需开口，直接生成阅读需求文档 + 初始化骨架图（dep-graph.md + knowledge.md）

学习路线输出

kernel-reading-guide 结合 kernel-graph MCP 查询结果，生成：

  • 按功能分类的"阅读后能解决的问题"清单
  • 关键源文件列表（文件路径 + 行号来自 MCP 真实查询）
  • 按知识依赖排序的阅读顺序建议
  • API → 文件快速检索表
  • 初始骨架图：用 call_chain_down depth=2 建立节点和调用边，Dashboard 知识图谱立刻有内容

输出到 learn/kprobe/kprobe_read_guide.md。Obsidian 不会自动同步，需要手动说“同步 obsidian”。也可随时手动触发：

你说："给我生成 kprobe 的学习路线"
# 或在 experiments/ 下新建 .c 文件后，Claude 自动建议生成
当前已有板块：以 .claude/memory/ 和 learn/ 目录为准；当前工程包含 sched、mpam、perf、ebpf、android_boot、vendor_hook 和 unclassified 等学习区。

Hooks（自动触发，无需开口）

Hook · PostToolUse
内核模块检查
Write/Edit → experiments/*.c
检测 #include <linux/module.h>，自动输出编译命令、MODULE_LICENSE 缺失警告、checkpatch 建议。Shell 脚本实现，条件不满足时完全静默。
Hook · Stop
会话结束自动化

asyncRewake 机制：必要时补全未 capture 的分析 → 写 learning-journal 今日条目 → 提示如需同步 Obsidian 请手动说“同步 obsidian”。
Hook · PostToolUse
Capture 提醒
Write/Edit → learn/*.md
写入学习笔记时记录变更到 /tmp/kernel-learning-changed.txt，并提醒确认是否已调用 kernel-learning-capture。
设计原则：条件判断类 Hook 用 Shell 脚本（静默可靠）；需要理解对话内容的行为放在 CLAUDE.md 规则里，不用 Hook。

Agents（专属子代理）

主会话识别到对应领域的问题时自动派遣，内置领域背景知识减少重复查询。

Agent
scheduler-analyst
专注 CFS/RT/Deadline/Idle 四类调度器。内置：sched_class 链表、vruntime 计算、RT prio_array、Deadline EDF+CBS、关键结构体速查。每次分析标注 SMP 安全性。
Agent
mpam-specialist
专注 ARM MPAM + resctrl。内置：PARTID/PMG/MSC 硬件模型、resctrl 层次图（VFS → rdtgroup → ctrlmondata → arch）、关键结构体速查。
Agent
perf-specialist
专注 perf_events 性能事件子系统分析。
Agent
ebpf-specialist
专注 eBPF 路径、概念和调用链分析。
Agent
android_boot-specialist
专注 Android 手机整机启动和运行相关内核路径。

新增学习板块时，add-learning-module skill 会自动生成对应的 specialist agent。

Memory（持久化学习状态）

存放在 .claude/memory/，随学习自动演化，也是本 Dashboard 的数据来源。

Memory
memory/{subsystem}/knowledge.md
每个子系统独立一个文件，记录函数/结构体的掌握状态。状态四档：mastered(≥80) · exploring(40-79) · unknown(<40) · questioned。含 Confluence 内部文档列。
Memory
memory/{subsystem}/dep-graph.md
该子系统的函数调用关系树（ASCII 格式）。kernel-reading-guide 初始化骨架，kernel-learning-capture 每次分析后补充精确边。Dashboard 知识图谱的数据来源。
Memory
open-questions.md
待解答问题，三级优先级：CRITICAL（阻塞）/ MEDIUM（重要）/ LOW（感兴趣）。每条含建议 MCP 查询命令。
Memory
learning-journal.md
按日期的会话日志，Stop hook 自动追加。记录：学习内容、知识状态变化、新增问题、下次建议。
Memory
MEMORY.md
索引文件，每次会话启动时 Claude 首先读取。含当前学习焦点（各板块进度描述）和最近 5 个分析记录。

排障

  1. 页面打不开：确认 ./start.sh 输出 Dashboard 已启动：http://localhost:7788，失败时查看 /tmp/kernel-dashboard.log。
  2. 数据不刷新：确认修改的是 .claude/memory/、learn/ 或 dashboard/manual_edges.json；这些是 SSE 监听范围。
  3. 图谱没有节点：检查对应子系统是否有 knowledge.md 和 dep-graph.md，或在调用链路图里确认笔记中是否存在可解析的 ASCII 调用树代码块。
  4. 端口占用：运行 cd /path/to/kernel-learning-workspace/dashboard && ./stop.sh 后再启动。
